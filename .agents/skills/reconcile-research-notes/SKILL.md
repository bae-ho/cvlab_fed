# 연구 기록 조정

[현재 근거](../../../docs/research/meeting-evidence.md)와 요청된 원본을 읽는다. PDF는 물리 페이지 번호를 보존한다. 추출이 비어 있거나 표/그림이 의미를 좌우하면 페이지 렌더링이나 OCR로 확인하고 읽지 못한 부분을 밝힌다.

새로운 내용을 결정, 목표, 제안, 결과, 열린 안건으로 구분한다. 날짜가 늦은 문서의 이전 회의 요약을 새로운 결정으로 취급하지 않는다. 정량 결과 없는 공유 문구나 비어 있는 action item에서 성능·담당·완료 상태를 추정하지 않는다.

관련 코드만 대조해 [구현 상태](../../../docs/research/implementation-status.md)를 갱신한다. 구현 존재와 실행 검증을 구분한다. PEL4VAD/HELP-VAD, CLAP 용어와 충돌하는 일정은 확인 전 동일성·정의·기한을 확정하지 않는다.

채택된 변경은 docs/decisions/에 원본·페이지·영향을 연결한다. 실험 안건은 [연구 검증 기준](../../../harness/checks/research-validation.md)과 필요한 작업 계획에 연결한다. 기존 근거 ID를 보존하고 변경 이유를 남긴다. 외부 논문을 확인하지 않았다면 회의의 조사 후보로 표시한다.

산출물은 출처가 연결된 요구/결정과 코드 차이, 열린 항목이다. 반복 절차가 확인된 경우에만 스킬을 추가하며 원본 전체를 스킬에 복제하지 않는다.

## 현행 범위와 실험 보고
[현행 목표](../../../docs/README.md#현행-연구-목표와-성능-정의)와 [두 트랙 경계](../../../docs/research/two-track-scope.md)를 우선한다. 집계 보고를 현재 PEL 작업의 집계 변경 지시나 최종 통합 결정으로 바꾸지 않는다.

[Slack 근거](../../../docs/research/slack-experiment-evidence.md)와 원본 표 이미지를 읽는다. 보고·표·로그의 날짜·설정·seed·run ID를 연결하고 충돌은 출처별로 보존한다. 별도 표의 조건을 상속하지 않고 best metric과 해당 checkpoint 지표, 계획과 완료를 구분한다.

## 공식 용어와 축약 표현 규칙
문서를 생성·정리·갱신할 때 [공통 용어 지침](../../../docs/writing-guidelines.md)을 반드시 따른다. 논문·명세·공식 문서에서 확인한 공식 용어와 공식 약어만 사용한다. 어시스턴트가 자체적으로 만든 축약 표현은 사용하지 않는다. 공식 명칭이 없는 실험·변형은 대상·방법·조건·목적이 이해되도록 풀어서 쓰며, 조사 생략과 단어 나열은 의미가 분명한 경우에만 허용한다.

제목·파일명·표의 행과 열·통합표·세미나 문서·도식 label·수식 설명·완료 보고에도 동일하게 적용한다. 코드 식별자·원본 로그는 정확히 인용하되 독자용 완전한 설명을 병기한다. 기존 기계 판독 필드를 임의 변경하지 않는다. 기존 스킬의 짧은 예시보다 이 규칙이 우선하며 저장 전에 공식성·명확성을 확인한다.
