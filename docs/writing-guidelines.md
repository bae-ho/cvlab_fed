# 문서 용어와 실험 이름 작성 지침

- 적용일: 2026-10-14
- 근거: 사용자 명시 지시
- 적용 범위: 문서의 생성·정리·갱신 전반. 실험 설계·결과 기록·통합 비교표·세미나 자료·회의 요약·설계 결정·LaTeX 표·표 이미지·Mermaid 도식·완료 보고에 동일하게 적용한다.

## 공식 용어와 약어
- 논문, 명세, 공식 문서에 적힌 공식 용어를 사용한다. 어시스턴트가 자체적으로 만든 축약어·약칭·줄임말은 사용하지 않는다.
- 약어는 논문·명세·공식 문서에 실제로 정의되거나 사용된 공식 약어만 허용한다. 단어의 앞글자를 조합하거나 내부 코드명을 설명 용어로 바꾸어 새로운 약어를 만들지 않는다.
- 공식 여부는 근거 문서에서 확인한다. 약어가 익숙하다는 이유로 공식으로 추정하지 않는다. 확인할 수 없으면 의미가 명확한 완전한 표현을 쓴다.
- 처음 등장하는 공식 약어는 필요한 경우 전체 명칭과 함께 쓰고 출처를 연결한다. 반복 사용 시에도 한 문서 안에서 동일한 명칭을 유지한다.
- 새 실험·구현 변형에 공식 이름이 없으면 대상·방법·조건·목적을 풀어서 설명한다. 설명용 이름을 논문에서 정의한 공식 방법론 이름인 것처럼 표시하지 않는다.

## 실험과 조건의 이름
- 파일명, 제목, 표의 행·열 이름, 그림 label, bullet point에서도 실험 대상과 조건을 이해할 수 있는 표현을 쓴다.
- 필요한 정보는 데이터셋, 클라이언트 분할, 적용 방법, 비교 기준, 변경 조건과 검증 목적이다. 각 위치에서 실험을 구별할 만큼 명시한다. 긴 설정은 별도 조건 열·설명으로 연결해 의미를 보존한다.
- 조사를 생략하고 단어를 나열하는 방식은 허용한다. 다만 대상·방법·조건 간 관계가 독자에게 이해되어야 하며 임의 축약을 허용하는 예외가 아니다.
- 예: 'AI Hub CCTV 데이터셋 사건별 클라이언트 분할 PEL4VAD 대조 손실 가중치 비교'처럼 쓴다. PEL4VAD 명칭은 해당 논문에서 확인한 경우에 사용한다. '+'만으로 서로 다른 집계·개인화·손실 조합의 의미를 대신하지 않는다.
- 문서에 이미 정의된 공식 명칭은 반복할 수 있지만 독자가 별도 대화를 읽어야만 뜻을 알 수 있는 내부 별칭은 쓰지 않는다.

## 코드 식별자와 원본 보존
- 실제 함수·CLI 인자·파일 경로·JSON 필드·로그 원문·기존 run ID는 추적과 호환성을 위해 정확히 인용한다. 이것을 설명용 공식 용어로 간주하지 않는다. 독자에게 보이는 설명은 완전한 표현으로 병기한다.
- 기존 기계 판독용 key와 파일명을 임의로 바꾸어 CSV 추출이나 회차 연결을 깨뜨리지 않는다. 새 식별자는 의미를 설명하는 이름으로 정하고 문서에서 대응을 정의한다.
- 기존 통합표에 코드값이 표시되는 경우 해당 값의 의미를 독자가 이해할 수 있도록 조건 설명 또는 용어 대응을 함께 제공한다. 코드값만 나열한 표를 최종 설명으로 사용하지 않는다.
- 원본 논문·회의록·로그에 비공식 표현이 있으면 직접 인용임을 밝히고 출처를 연결한다. 작성자가 만든 설명에서는 그 표현을 무비판적으로 재사용하지 않는다.

## 저장 전 확인
- 제목·실험 이름·표·도식·수식의 설명과 본문에서 임의 축약을 제거했는가?
- 사용한 약어마다 공식 근거가 있는가? 없는 경우 풀어서 썼는가?
- 실험 방법·데이터셋·분할·조건·평가 지표의 의미가 대화 맥락 없이도 이해되는가?
- 코드 식별자의 정확성과 독자용 설명을 함께 보존했는가?
- 기존 문서를 정리·갱신할 때 변경 범위에서 발견한 임의 축약을 공식 용어나 완전한 표현으로 고쳤는가?

이 지침은 기존 스킬·템플릿의 간략한 이름 예시보다 우선한다. 공식성 검증 없이 기존 예시를 새 문서의 표현으로 복사하지 않는다.
