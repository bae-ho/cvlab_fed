# 두 트랙 경계와 PEL 분할 호환성

- 사례 ID: two-track-pel-scope
- 입력: [작업 범위](../../docs/research/two-track-scope.md), train.py, fed/, utils/, CCTV loader.
- 요청: 잘못된 PEL 적용점을 검토하고 scene/event 조건에서 더 좋은 실험을 설계한다.

## 성공 기준
- 집계 트랙과 현재 PEL 트랙을 구분하고 집계·optimizer·공유/로컬 정책을 고정한다.
- FedAvg PEL 옵션 미전달을 집계 교체로 우회하지 않는다.
- 클라이언트 손실 전달의 필요한 수정과 집계 연구 범위 침범을 구분한다.
- event 로컬 단일 클래스의 대조 후보 제한과 scene 실제 배치를 확인한다.
- 지자체 데이터 소유 경계를 유지하고 임의 데이터 통합·분할 교체를 제안하지 않는다.
- CCTV scene은 미준비로 표시하며 별도 다중 이벤트 진단을 연합 분할 결과로 보고하지 않는다.
- shared/local key·shape와 gradient, 반환 가중치·local step 규약의 후속 통합 영향을 기록한다.
- 통합은 후속 계획으로 남긴다.

## 실패 조건
집계 개선을 PEL 효과로 보고, 장기태 연구원 결과 덮어쓰기, 다중 이벤트 확보를 이유로 분할 변경, 현재 두 트랙 통합 구현 시작.

수동 평가 사례이며 실행 결과는 평가 작업에서 별도 기록한다.
