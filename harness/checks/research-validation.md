# 연구 검증 기준

근거: [회의 요구](../../docs/research/meeting-evidence.md), [코드 상태](../../docs/research/implementation-status.md). 아래는 하네스 운영 기준 제안이며 회의에서 지정하지 않은 수치 목표는 추가하지 않았다.

현행 성능 목표와 비교 정의는 [프로젝트 지식 지도](../../docs/README.md#현행-연구-목표와-성능-정의)를 따른다. SOTA는 사용자 지정 목표이며 달성 사실과 구분한다. 과거 요구의 unseen, domain gap, 실시간 및 프라이버시 실증 항목은 해당 주장을 하는 작업에서 적용하며 현재 벤치마크 성능 목표의 필수 항목으로 자동 추가하지 않는다.

## 동작 확인과 성능 확인
동작 확인: loss/gradient/출력의 유한 값, 의도한 파라미터 gradient, 유효 데이터 batch, 실제 업데이트, 옵션을 끈 기준 경로를 확인한다. 대조학습 로스가 출력됐다는 사실만으로 성능 개선을 주장하지 않는다.
성능 확인: 동일 데이터·분할·초기화·학습 예산·평가 정책으로 기준/후보 ROC-AUC와 AP 및 delta를 기록한다. 스케일이 0–1인지 백분율인지 명시한다. 로그 없는 값을 채우지 않는다.

## 단일 로컬 PEL
- CCTV/UCF 단일 라벨 경로를 사용한다. XD 다중 라벨에 그대로 적용하지 않는다.
- normal/anomaly loader 모두 batch가 1개 이상인지 확인한다. drop_last와 작은 클라이언트로 0 batch가 될 수 있다.
- Normal 인덱스, 클래스 인덱스, 특징 (B,T,C), 텍스트 (K,C), logits (B,T,K)가 일치해야 한다.
- 이벤트 클래스, 클래스별 의미 표현과 실제 대조 후보를 구분한다. dictionary 확장 시 손실에서 선택된 클래스와 다중 이벤트 배치 구성을 확인한다.
- 스니펫 패딩이 pooling과 점수에 들어가는지 점검한다. 전부 패딩인 입력은 유효 샘플로 다루지 않는다.
- 기존 스크립트는 공통 테스트셋을 쓰는 proxy 비교다. 로컬 held-out이나 strict zero-shot 결과로 표기하지 않는다.

## 연합 집계와 어블레이션
- 공유/로컬 파라미터 key가 중복되지 않고 필요한 학습 파라미터를 덮는지 확인한다.
- 공유 업데이트가 올바른 표본 가중치로 평균되는지, 글로벌 배포 후 로컬 어댑터가 보존되는지 작은 텐서나 제한된 라운드로 확인한다.
- 집계 방식, 서버 optimizer, 개인화, PEL 손실은 독립 축으로 기록한다. 한 번에 바꾼 요인이 여러 개면 결합 효과로 보고한다.
- FedProx 기준 anchor, FedNova 실제 local step 수 등 적용한 방식의 상태를 확인한다.
- n_ctx는 생성기, X 자리 수, 클래스 토큰/EOT 위치, 개인화 shape를 함께 확인한다. prefix/postfix를 바꾼 실험을 n_ctx 실험으로 이름 붙이지 않는다.
- 마스크 적용은 패딩 무시 정확성을 확인하는 항목이다. -inf가 자동으로 FLOPs 감소를 보장한다고 주장하지 않는다. 전부 마스킹된 행의 NaN 여부도 확인한다.

## 데이터와 성능 주장
- manifest/CSV/GT 순서, 영상별 유효 길이, 특징 차원과 추출 stride를 확인한다. 현재 평가는 np.repeat(score,16) 방식이다.
- 원 영상·세션·카메라 기준으로 train/validation/test 중복 여부를 기록한다. Normal 자료를 여러 클라이언트가 공유하면 집계 가중치 해석에 반영한다.
- unseen 성능을 별도로 주장하는 경우에만 클래스가 전체 학습 클라이언트와 감독 라벨에서 제외됐는지 확인한다. 사전학습 VLM의 노출 범위와 테스트 때 텍스트 클래스 제공 정책은 별도로 기술한다.
- domain gap/FPR은 로컬 도메인 분할과 validation에서 정한 threshold가 필요하다. 공통셋 AP 개선으로 대체하지 않는다.
- 실시간 실증은 하드웨어, 입력 FPS, 추출·전송·추론 포함 범위, latency 분포와 처리량을 기록한다. 캐시 특징 추론 시간과 구별한다.
- 원본 비반출 목표는 서버에 전달하는 항목과 로그/특징/gradient 흐름을 확인한다. 연합학습만으로 정보 유출 방지나 DP/암호화 보장이 검증됐다고 쓰지 않는다.

새 실험 명령 안내·학습 전에 목적·설계 근거·비교 조건·측정·해석 기준을 사용자에게 설명하고 사전 문서로 저장한다. 실험명은 데이터셋·분할·방법·검증 목적을 풀어 쓰며 스크립트 약칭만으로 설명하지 않는다. 장시간 학습 전에 환경·데이터·자원·실행 범위를 확인한다. 미검증은 실패와 구분해 이유와 다음 확인을 기록한다.

## 트랙 경계와 분할 호환성
- [두 트랙 범위](../../docs/research/two-track-scope.md)를 따른다. 현재 PEL 비교의 집계 수식·가중치·서버 optimizer·공유/로컬 정책은 고정한다.
- PEL 전달을 고쳐야 할 때 집계 동작·반환 가중치·local step 규약을 보존한다. 다른 집계 방식으로 우회하지 않는다.
- scene/event별 라벨 매핑, 로컬 클래스와 배치 후보, 유효 길이, 공유 gradient를 검증한다. PEL 때문에 클라이언트 데이터나 분할을 합치지 않는다.
- 다중 이벤트 로컬 진단은 별도 조건으로 표시한다. CCTV scene은 메타데이터와 분할 준비 전 실행 가능으로 표기하지 않는다.
- 이후 통합에 영향을 주는 key/shape와 상태를 기록한다. 통합 자체는 현재 범위가 아니다.

## 보고·통계 대조
[Slack 근거](../../docs/research/slack-experiment-evidence.md)를 읽고 요약·표·원시 로그, 날짜·run ID·설정 출처를 구분한다. momentum 포함/제외 조건을 상속하지 않는다. 최고 ROC round AP, 독립 최고 AP, 최종 성능과 전체 곡선을 분리한다. round 변동은 seed 분산이 아니다. seed별 delta·평균·표준편차·표본 수를 기록하고 미완료 상태를 보존한다. Scene의 Non-IID 원인 설명은 분포 통계로 검증한다. 비용 측정은 입력 shape, trainable/total params, 연산 단위, 메모리·지연·처리량을 명시하며 요청 범위에서 수행한다.
