# 변경별 검증 기준

| 변경 | 검증 |
| --- | --- |
| 문서와 폴더 | 파일 존재, 상대 링크, 코드와 설명의 일치 |
| 설정 또는 CLI | 인자 정의와 소비 코드 확인, 환경이 준비되면 --help 실행 |
| 모델 또는 집계 | 작은 입력으로 shape, 유한 값, 공유/로컬 파라미터 보존 확인 |
| 데이터 처리 | 소규모 샘플로 경로, 라벨, 분할 누수 확인 |
| 실험 로직 | 동일 데이터·분할·시드·학습 예산으로 기준 결과와 비교 |

검증 기록에는 명령, 환경, 결과, 로그 경로를 포함한다. 미실행 검증은 이유와 함께 표시한다.
고정 전체 클래스 PEL의 CPU 자동 검증은 `python -m unittest discover -s tests -v`로 실행한다. CI 연결은 아직 없다. [실행 안내](../../docs/research/fixed-bank-pel-run.md)를 참고한다.

## VAD 성능 및 PEL 변경 확인

성능 목표와 성공 기준은 [프로젝트 지식 지도](../../docs/README.md#현행-연구-목표와-성능-정의)를 따른다. 방법론 사실은 [PEL 적용 분석](../../docs/architecture/pel4vad-integration.md)을 참고한다.

- PEL 옵션을 정의한 위치부터 실제 서버·클라이언트 손실까지 소비 경로를 추적한다.
- dictionary 항목 수와 실제 대조 denominator의 클래스 구성을 별도로 확인한다.
- 다중 이벤트 변경 시 문자열 라벨과 class index의 대응, 배치 내 이벤트 구성을 확인한다.
- 길이 mask가 attention, pooling과 추론의 유효 구간에 일관되게 적용되는지 확인한다.
- 성능 비교는 동일 조건의 기준 모델과 수행하고, 논문 보고 수치 비교는 따로 표기한다.
- SOTA는 목표와 달성 사실을 구분하고 비교군·설정·지표의 근거를 남긴다.

연구 실험은 [회의 기반 연구 검증 기준](research-validation.md)을 함께 적용한다.


문서·표·그림 검증 시 [공통 용어 지침](../../docs/writing-guidelines.md)에 따라 공식 용어·약어 근거, 자체 축약 부재, 실험 대상·조건의 명확성을 확인한다.
